I 
Что такое замыкание (closure) в JavaScript?

Замыкание (closure) в JavaScript — это функция, которая «помнит» и имеет доступ к переменным из своей внешней (родительской) области видимости, даже после того, как внешняя функция завершила свое выполнение. В JavaScript все функции являются замыканиями, так как они автоматически запоминают место своего создания.

Как работают замыкания:
Лексическое окружение: Функция сохраняет ссылку на окружение, в котором была создана.
Доступ к переменным: Внутренняя функция может использовать переменные, аргументы и функции, объявленные снаружи.
Сохранение данных: Замыкание живет, пока на него есть ссылки, позволяя «прятать» переменные и создавать приватные данные.

Простой пример:
function createCounter() {
  let count = 0; // Переменная во внешней области
  return function() { // Внутренняя функция (замыкание)
    count++;
    return count;
  };
}

const counter = createCounter();
console.log(counter()); // 1
console.log(counter()); // 2 (функция помнит переменную count)


Зачем нужны замыкания:
Инкапсуляция данных: Создание «приватных» переменных, недоступных из глобальной области.
Функциональные фабрики: Создание специализированных функций.
Сохранение контекста: Часто используются в асинхронном коде, обработчиках событий (onclick) и колбэках. 
В JavaScript каждый раз, когда функция создается, создается и замыкание.

II.
Объясните разницу между var, let и const.

В JavaScript var, let и const используются для объявления переменных, различаясь областью видимости, подъемностью (hoisting) и возможностью переопределения. let и const — современный стандарт (ES6) с блочной областью видимости, в то время как var — устаревший подход с функциональной областью видимости. В современной разработке рекомендуется использовать const по умолчанию, let — при необходимости изменения значения, и избегать var.

Вот основные различия:
1. var (устаревший)
Область видимости: Функциональная (переменная видна во всей функции).
Поднятие (Hoisting): Поднимается в начало области видимости и инициализируется как undefined.
Переопределение: Можно переопределять и обновлять в одной области видимости.
Пример:
if (true) {
    var x = 10;
}
console.log(x); // 10 (видима вне блока)


2. let (современный)
Область видимости: Блочная (видима только внутри {} ).
Поднятие (Hoisting): Поднимается, но не инициализируется. Обращение до объявления вызывает ReferenceError.
Переопределение: Можно обновлять (изменять значение), но нельзя повторно объявлять в той же области видимости.
Пример:
if (true) {
    let y = 10;
}
console.log(y); // ReferenceError: y is not defined

3. const (современный)
Область видимости: Блочная (видима только внутри {} ).
Поднятие (Hoisting): Поднимается, но не инициализируется (аналогично let).
Переопределение: Нельзя переопределять или обновлять. Значение должно быть присвоено при объявлении.
Особенность: Если const хранит объект или массив, его содержимое можно изменять (добавлять свойства/элементы), но нельзя присвоить новую ссылку. 

Итоговая таблица
Характеристика	var	let	const
Область видимости	Функция	Блок {}	Блок {}
Переопределение	Да	Да	Нет
Переобъявление	Да	Нет	Нет
Поднятие	undefined	Ошибка (TDZ)	Ошибка (TDZ)
Инициализация	Необязательно	Необязательно	Обязательно

Когда что использовать?
const: По умолчанию для всех переменных, значение которых не планируется переназначать.
let: Только если вы знаете, что значение переменной нужно будет изменить (например, в циклах).
var: Не использовать в современном JS. 

III.
Чем отличается == от === в JavaScript?

Основное отличие == (нестрогое равенство) от === (строгое равенство) в JavaScript заключается в приведении типов. Оператор == преобразует типы данных перед сравнением (например, 5 == '5' — true), тогда как === проверяет и значение, и тип данных, возвращая false при их несовпадении (например, 5 === '5' — false). Для избежания ошибок рекомендуется использовать ===.

Ключевые различия:
== (Абстрактное равенство): Преобразует операнды к одному типу (приведение типов) перед сравнением.
1 == '1' -> true
null == undefined -> true
0 == false -> true
=== (Строгое равенство): Сравнивает значения, не выполняя преобразование типов. Если типы разные, результат сразу false.
1 === '1' -> false
null === undefined -> false
0 === false -> false

Что такое Promise и для чего он используется?

Promise (промис) — это специальный объект в JavaScript, представляющий результат незавершенной асинхронной операции. Он выступает «обещанием» вернуть значение (успешный результат или ошибку) в будущем, позволяя работать с асинхронным кодом, как с синхронным, и избегать сложной вложенности колбэков.

Основные аспекты Promise:
Назначение: Используется для обработки асинхронных задач (запросы к API, чтение файлов, таймеры), делая код более читаемым, предсказуемым и управляемым.
Состояния:
Pending (ожидание): Начальное состояние, операция еще не завершена.
Fulfilled (выполнено успешно): Операция завершилась успешно, результат доступен.
Rejected (отклонено): Операция завершилась ошибкой.
Методы обработки:
.then(): Выполняется, если промис перешел в состояние fulfilled.
.catch(): Выполняется, если промис перешел в состояние rejected.
.finally(): Выполняется в любом случае после завершения промиса.

Решение проблемы Callback Hell: Промисы позволяют объединять асинхронные действия в цепочки (chaining), что делает код линейным и понятным.

V.
Что такое REST API и какие у него основные принципы?

REST API (Representational State Transfer) — это архитектурный стиль взаимодействия компонентов распределенных приложений, основанный на протоколе HTTP. Он позволяет клиенту (браузеру, приложению) получать или изменять данные на сервере, используя стандартные методы (GET, POST, PUT, DELETE) и уникальные URI ресурсов, обычно обмениваясь данными в формате JSON.

Основные принципы REST API:
Клиент-серверная архитектура: Четкое разделение ответственности: клиент запрашивает данные, сервер их обрабатывает и хранит. Это позволяет развивать их независимо.
Отсутствие состояния (Stateless): Сервер не хранит информацию о предыдущих запросах клиента. Каждый запрос должен содержать всю необходимую информацию для его обработки (аутентификацию, параметры).
Кеширование (Cacheability): Ответы сервера могут кэшироваться, чтобы снизить нагрузку и ускорить работу приложений.
Единообразие интерфейса (Uniform Interface): Использование стандартных HTTP-методов (GET — получить, POST — создать, PUT/PATCH — обновить, DELETE — удалить) и унифицированных URI для ресурсов (например, /users/123).
Многоуровневая система (Layered System): Архитектура может включать промежуточные узлы (прокси, балансировщики нагрузки), что улучшает масштабируемость и безопасность.
Код по требованию (Code on Demand): Дополнительный принцип, позволяющий серверу передавать клиенту исполняемый код (например, скрипты).
